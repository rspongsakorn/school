# แก้รายงานการเงิน ข้อ 1–3 (รายบุคคล, ค้างชำระ, สถิติการเก็บ)

วันที่ 2026-11-26 · ขนาด: งานเล็ก · อนุมัติแล้วในบทสนทนา

## ที่มา

ตรวจเมนู "รายงาน" ทั้ง 6 หน้าผ่านเบราว์เซอร์บนฐานทดสอบ `school` (admin, ภาค 1/2569) แล้วเจอสามจุดที่ตัวเลขผิดหรือชวนเข้าใจผิด
จึงแก้สามจุดนี้ก่อน ส่วนเรื่องการนำทาง ความเร็ว และการจัดเมนูทำทีหลัง

1. หน้ารายบุคคล (`/reports/students`) แสดง 1,857 แถว แต่มีนักเรียนจริงแค่ 926 คน เพราะแสดงหนึ่งแถวต่อหนึ่งใบแจ้ง
   ทำให้คนเดียวขึ้นหลายแถว (เช่นรหัส 14297 ขึ้นสองแถว ฿0 กับ ฿2,900) และคอนโซลแจ้ง React duplicate key
2. หน้ารายงานค้างชำระ (`/reports/outstanding`) ตั้งต้นที่ "ทุกสถานะ" จึงแสดงใบที่ชำระแล้วปนมา 1,537 จาก 1,857 แถว
   และมุมมองแบบรายชื่อไม่มีแถวยอดรวม
3. หน้าสถิติการเก็บ (`/reports/collections`) มุมมอง "ทั้งหมด" แสดง 0 คน / ฿0 / 0% อยู่ราว 10 วินาทีระหว่างโหลด
   และมุมมอง "ตามห้อง" ไม่มีทั้งสถานะกำลังโหลดและข้อความเมื่อไม่มีข้อมูล

## เป้าหมาย

- หน้ารายบุคคลแสดงหนึ่งแถวต่อหนึ่งคน และตัวกรองสถานะกรองตามสถานะรวมของคนนั้น
- หน้าค้างชำระเปิดมาเห็นเฉพาะใบที่ยังค้าง (ทั้งค้างเต็มใบและจ่ายบางส่วน) โดยยังเลือกดูทุกสถานะได้
- หน้าค้างชำระมีแถวยอดรวมในมุมมองแบบรายชื่อ
- หน้าสถิติไม่แสดงตัวเลขศูนย์ปลอมระหว่างโหลด

## ไม่ทำในรอบนี้

- ความเร็วในการโหลด (ยิงคำขอไปฐานข้อมูล 22 ครั้ง ใช้เวลา 13–15 วินาที) และการแบ่งหน้า
- การเก็บตัวกรองไว้ใน URL ในหน้ารายรับรายวัน ส่วนลด สถิติ และรายบุคคล
- เมนูด้านข้างที่หุบอยู่, การเปลี่ยนภาคในหน้าใบแจ้งยอดแล้วถูกพาออก, ชื่อหน้าไม่ตรงกัน, ลำดับเมนู
- บั๊กเมนูของครู และข้อความผิดในหน้า login
- การรวมหน้ารายบุคคลเข้ากับมุมมอง "รวมรายคน"

## ข้อห้าม

- ไม่แตะฐานข้อมูลและไม่เพิ่ม migration
- ห้ามทำให้ยอดเปลี่ยน: ยอดรวมค้างของภาค 1/2569 ต้องเท่าเดิมที่ ฿864,575 ทั้งในหน้าค้างชำระและหน้ารายบุคคล

## แนวทางที่พิจารณา

| แนวทาง | ข้อดี / ข้อเสีย | ผล |
|---|---|---|
| **รวมยอดรายคนฝั่งหน้าเว็บด้วย `aggregateOutstandingByStudent` ที่มีอยู่แล้ว** | ไม่ต้องแตะฐานข้อมูล ใช้ตรรกะเดียวกับมุมมอง "รวมรายคน" ที่ผ่านการทดสอบแล้ว | **เลือก** |
| รวมยอดใน SQL (สร้าง view หรือ RPC ใหม่) | เร็วกว่า แต่ต้องมี migration และขยายงานเกินที่ต้องการ | ไม่เลือก |

## แบบที่อนุมัติ

### 1. หน้ารายบุคคล
- `fetchStudentRoster` ดึงข้อมูลรายใบแจ้งทุกสถานะ (`status: "all"`, `includeAllStatuses: true`) แล้วส่งต่อให้ฟังก์ชันใหม่ที่ไม่ยุ่งกับฐานข้อมูลใน `src/lib/reports/` ซึ่งทำสามอย่างตามลำดับ:
  1. รวมยอดรายคนด้วย `aggregateOutstandingByStudent` (ผลลัพธ์เรียงตามรหัสนักเรียนอยู่แล้ว)
  2. กรองตามสถานะรวมของคน (`unpaid` / `partial` / `paid`) **ทำหลังรวมยอด** *(ผู้พัฒนาเป็นคนเลือก)*
  3. กรองตามชื่อหรือรหัส
- คอลัมน์ของตารางเหมือนเดิม และ type `StudentRosterRow` ไม่เปลี่ยนรูป

### 2. หน้าค้างชำระ
- เพิ่มค่าสถานะ `outstanding` ในตัวเลือกชื่อ "ยังค้างชำระ" และใช้เป็นค่าเริ่มต้นเมื่อ URL ไม่มี `status`
- ตัวเลือกเรียงเป็น: ยังค้างชำระ · ค้างชำระ (ยังไม่จ่าย) · ชำระบางส่วน · ชำระแล้ว · ทุกสถานะ
- ค่า `outstanding` ส่งไปที่ `fetchOutstandingReport` เป็น `status: "all"` คู่กับ `includeAllStatuses: false` ซึ่ง query รองรับอยู่แล้ว (กรอง `in ('unpaid','partial')`)
- "ทุกสถานะ" เก็บใน URL เป็น `status=all` ส่วนค่าเริ่มต้นไม่ต้องใส่ param
- ป้าย "ค้างชำระ" ของสถานะ `unpaid` เดิมเปลี่ยนเป็น "ยังไม่ชำระ" ในตัวเลือก เพื่อไม่ให้สับสนกับ "ยังค้างชำระ" *(ผู้พัฒนาเป็นคนเลือก)*
- เพิ่มแถวยอดรวมท้ายตารางมุมมองแบบรายชื่อ: จำนวนใบ, ค่าใช้จ่าย, ต้องชำระ, ชำระแล้ว, ค้าง

### 3. หน้าสถิติการเก็บ
- มุมมอง "ทั้งหมด": ระหว่างโหลดแสดงกล่องกำลังโหลดแทนการ์ดตัวเลข
- มุมมอง "ตามห้อง": มีทั้งสถานะกำลังโหลดและข้อความ "ไม่มีข้อมูล" แบบเดียวกับมุมมอง "ตามชั้น"

## การตรวจสอบ

- มี unit test ของฟังก์ชันรวมยอดรายคนพร้อมตัวกรอง ครอบคลุมกรณี: หลายใบต่อคน, กรองสถานะหลังรวมยอด, ค้นหาชื่อ/รหัส
- `npm test`, `npm run lint` และ `tsc` ต้องผ่าน
- ตรวจผ่านเบราว์เซอร์บนฐาน `school`:
  - หน้ารายบุคคลมีจำนวนแถวเท่ากับจำนวนคน และไม่มี duplicate key ในคอนโซล
  - หน้าค้างชำระตั้งต้นเห็นเฉพาะใบที่ยังค้าง และยอดรวมเท่ากับ ฿864,575
  - หน้าสถิติไม่แสดงเลข 0 ระหว่างโหลด
